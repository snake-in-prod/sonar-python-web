An async def endpoint runs on the server's event loop together with every other request. A blocking call there (an HTTP request with requests or a sync httpx client, time.sleep, opening a file, a synchronous database driver or SQLAlchemy Session, the Django ORM, a subprocess) stops the loop until it returns: every other request waits. The Django ORM also raises SynchronousOnlyOperation in async code.

The rule checks async FastAPI and Django endpoints, the async project functions they call, and the sync project functions those call directly (the issue is then on the call, with the way to the blocking call as secondary locations; a local file read in such a helper is not reported). Calls that are awaited, passed to asyncio.to_thread, sync_to_async, run_in_threadpool or run_in_executor, or inside a lambda are not blocking. Flask runs each async view in its own event loop, so its views are not checked.

Noncompliant code example

@app.get("/rate")
async def rate():
    return requests.get(RATES_URL).json()  # Noncompliant

async def item_detail(request, pk):
    item = Item.objects.get(pk=pk)  # Noncompliant

Compliant solution

@app.get("/rate")
async def rate():
    async with httpx.AsyncClient() as client:
        return (await client.get(RATES_URL)).json()

async def item_detail(request, pk):
    item = await Item.objects.aget(pk=pk)

Or declare the endpoint with a plain def: FastAPI then runs it in a worker thread.
