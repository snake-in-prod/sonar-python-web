A view that changes data for a user signed in by a session cookie has its CSRF protection turned off. The browser sends the cookie with every request, so any page the user visits can submit a form or a script request to this view and act as the user.

Reported: Django @csrf_exempt (on the function, through method_decorator on the class or its dispatch, or as csrf_exempt(view) in urls.py) and Flask-WTF @csrf.exempt, on a view that accepts POST, PUT, PATCH or DELETE (or any method), writes data, and either requires a session login (login_required, an auth mixin, a request.user or current_user check) or acts on request.user.

Not reported: views that authenticate by a token, an API key, an Authorization header or a signature (webhooks), Django REST framework views (DRF enforces CSRF itself for session authentication), views that only read, and views that accept only GET.

Noncompliant code example

@csrf_exempt
@login_required
def transfer(request):  # Noncompliant
    Account.objects.filter(owner=request.user).update(balance=0)

Compliant solution

@login_required
@require_POST
def transfer(request):
    Account.objects.filter(owner=request.user).update(balance=0)

Send the CSRF token with script requests (the X-CSRFToken header) instead of turning the check off.
