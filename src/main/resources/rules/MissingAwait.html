Calling an async def function only creates a coroutine; nothing runs until it is awaited or scheduled. A coroutine call on a line of its own, or assigned to a name that is never awaited, is dropped: the email is not sent, the record is not saved, and Python only prints "coroutine was never awaited" at run time.

The rule checks async functions for calls of project async def functions (not decorated, not async generators), of asyncio.sleep, asyncio.wait_for and asyncio.wait, and of the async methods of FastAPI / Starlette Request (json, body, form), UploadFile (read, write, seek, close) and WebSocket parameters, and of SQLAlchemy / SQLModel AsyncSession parameters (commit, rollback, refresh, execute, delete, get...; an Annotated[AsyncSession, Depends(...)] alias is followed). A coroutine passed on (asyncio.create_task(notify()), gather, background_tasks.add_task), returned, or awaited later is not reported.

Noncompliant code example

@app.post("/users/{user_id}/notify")
async def notify(user_id: int):
    notify_user(user_id)  # Noncompliant: never runs

@app.post("/echo")
async def echo(request: Request):
    data = request.json()  # Noncompliant: data is a coroutine
    return {"name": data["name"]}

Compliant solution

@app.post("/users/{user_id}/notify")
async def notify(user_id: int):
    await notify_user(user_id)

@app.post("/echo")
async def echo(request: Request):
    data = await request.json()
    return {"name": data["name"]}
