Reading a related object on each row of a Django queryset makes one more query per row: a list of 100 orders that shows each order's customer runs 101 queries. select_related fetches ForeignKey and OneToOneField relations in the same query (a join); prefetch_related fetches ManyToMany and reverse relations in one more query for all rows.

This rule reports, in a for loop or a comprehension over Model.objects... (built in the loop or assigned once in the function), the first read of each relation of the loop variable when the queryset has no select_related or prefetch_related: order.customer for a ForeignKey or OneToOneField, order.tags.all(), count(), exists(), first() or last() for a ManyToMany field or a reverse relation (related_name or <model>_set). It stays silent for models with a custom manager, querysets passed in from elsewhere or changed after they are built, values() and values_list(), prefetch_related_objects, and *_id reads.

Noncompliant code example

def order_list(request):
    rows = []
    for order in Order.objects.filter(paid=True):
        rows.append((order.customer.name, [t.label for t in order.tags.all()]))  # Noncompliant (twice)
    return JsonResponse(rows, safe=False)

Compliant solution

def order_list(request):
    rows = []
    for order in Order.objects.filter(paid=True).select_related("customer").prefetch_related("tags"):
        rows.append((order.customer.name, [t.label for t in order.tags.all()]))
    return JsonResponse(rows, safe=False)
