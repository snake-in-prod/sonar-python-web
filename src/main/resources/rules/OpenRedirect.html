Request data passed as the target of Django redirect() or HttpResponseRedirect, Flask or Werkzeug redirect(), or a FastAPI / Starlette RedirectResponse sends users anywhere from a link on the trusted site: a phishing page that looks like the login form, or a page that steals an OAuth code. A check that the target starts with / is not enough: //evil.example passes it.

The issue names the endpoint the data comes in through and shows its path to the call.

Noncompliant code example

def login_done(request):
    return redirect(request.GET["next"])  # Noncompliant

Compliant solution

def login_done(request):
    target = request.GET.get("next", "/")
    if not url_has_allowed_host_and_scheme(target, allowed_hosts={request.get_host()}, require_https=request.is_secure()):
        target = "/"
    return redirect(target)

When the rule stays silent

  • The target is checked with url_has_allowed_host_and_scheme, an is_safe_url helper, an allow-list (target in ALLOWED), or a condition on its netloc or hostname, or one that excludes "//", or a URL check helper runs on the way (validate_redirect_url(...)).
  • The request data comes after a literal path, host or query start: f"/items/{slug}/", "/docs/" + page, url += f"&page={n}".
  • The target comes from a header or a cookie (a Referer sends users back where they came from), or is built by reverse() or url_for().
