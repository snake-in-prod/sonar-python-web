A FastAPI endpoint sends a password hash or a secret to the client. Without a response_model (or a return annotation), FastAPI serializes every attribute of the returned object, so an ORM User goes out with its hashed_password. A response model that itself has the field leaks it the same way.

Reported: the response model or return annotation is a project class with a password, secret or hash field; or there is none and the endpoint returns an object of such a class (loaded with db.get(User, id), db.query(User)..., select(User), User.objects..., built with User(...), a dependency parameter typed User, or a project function returning one), or a dict whose password key is read from an object.

Not reported: response models without such fields, response_model_exclude and response_model_include, SecretStr fields, fields declared with exclude=True or deferred columns, queries narrowed to some columns or counted, and anything the analysis cannot follow.

Noncompliant code example

@app.get("/users/{user_id}")
def read_user(user_id: int, db: Session = Depends(get_db)):
    return db.get(User, user_id)  # Noncompliant: User has hashed_password

Compliant solution

class UserOut(BaseModel):
    id: int
    email: str

@app.get("/users/{user_id}", response_model=UserOut)
def read_user(user_id: int, db: Session = Depends(get_db)):
    return db.get(User, user_id)
