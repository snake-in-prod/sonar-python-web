Request data that reaches a shell lets the caller run any command on the server: a ;, |, $(...) or a back-quote in the value starts a second command. This rule follows request inputs across functions and modules to os.system(), os.popen(), subprocess.getoutput() and getstatusoutput(), asyncio.create_subprocess_shell() and the subprocess functions called with shell=True.

Values quoted with shlex.quote(), cast with int(), typed int in FastAPI or by a URL converter, checked against an allow-list, with isalnum() or with re.fullmatch() do not count. An argument list given to shell=True whose first item is a literal program is not reported: the other items are only the shell's positional parameters. The issue names the endpoint and shows the path from the input to the call.

Noncompliant code example

def ping(request):
    host = request.GET["host"]
    os.system("ping -c 1 " + host)  # Noncompliant

@app.route("/convert", methods=["POST"])
def convert():
    subprocess.run("convert in.png -resize %s out.png" % request.form["size"], shell=True)  # Noncompliant

Compliant solution

Run the program with an argument list and no shell, or quote each value.

def ping(request):
    host = request.GET["host"]
    subprocess.run(["ping", "-c", "1", host], check=True)

@app.route("/convert", methods=["POST"])
def convert():
    subprocess.run(["convert", "in.png", "-resize", request.form["size"], "out.png"], check=True)
