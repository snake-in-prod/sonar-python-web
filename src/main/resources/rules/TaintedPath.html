Request data that ends up in a file path given to open(), aiofiles.open(), the pathlib read_text / read_bytes / write_text / write_bytes / unlink methods, Flask send_file, a FileResponse, os.remove or shutil.rmtree lets a caller pick another file with ../ or an absolute path. They can then read secrets, overwrite code or delete data. os.path.join(BASE, name) does not help: an absolute name replaces BASE.

The issue names the endpoint the data comes in through and shows its path to the call, across functions and modules.

Noncompliant code example

@app.route("/files/<path:name>")
def download(name):
    return send_file(os.path.join(UPLOADS, name))  # Noncompliant

@router.post("/upload")
async def upload(file: UploadFile):
    (BASE / file.filename).write_bytes(await file.read())  # Noncompliant: the client picks the file name

Compliant solution

@app.route("/files/<path:name>")
def download(name):
    return send_from_directory(UPLOADS, name)

@router.post("/upload")
async def upload(file: UploadFile):
    target = (BASE / secure_filename(file.filename)).resolve()
    if not target.is_relative_to(BASE):
        raise HTTPException(400)
    target.write_bytes(await file.read())

When the rule stays silent

  • The value went through os.path.basename, secure_filename, safe_join, int() or another cast.
  • A condition on the way checks the path: startswith, is_relative_to, os.path.commonpath, realpath / abspath / resolve() compared, or a test for "..".
  • The value is a URL path parameter whose converter cannot match / (Django and Flask str, FastAPI without :path), or a FastAPI parameter typed int, UUID and the like.
  • The value comes from a model class that validates its fields (a Pydantic field_validator, validator or model_validator): the rule cannot tell what the validators let through.
