Request data that is pasted into an SQL string lets the caller change the query: read other rows, bypass a WHERE clause, or modify and drop tables. This rule follows request inputs (Django request.GET, POST, DRF request.data, FastAPI query, path and body parameters, Flask request.args, form, json, URL parameters) across functions and modules to raw SQL: cursor.execute() and its variants, Django raw(), extra() and RawSQL, SQLAlchemy text() and execute(), asyncpg and databases fetch methods, and pandas.read_sql().

It reports only when the query string is built on the way, with an f-string, %, + or .format(). Values cast with int(), FastAPI parameters typed int, UUID, Literal or an Enum, Django and Flask URL parameters with an int converter, values checked against an allow-list (if column not in ALLOWED) or with isdigit() or re.fullmatch() do not count. The issue names the endpoint and shows the path from the input to the query.

Noncompliant code example

def search(request):
    q = request.GET.get("q", "")
    with connection.cursor() as cursor:
        cursor.execute(f"SELECT * FROM item WHERE name = '{q}'")  # Noncompliant

@app.get("/products")
def products(term: str, db: Session = Depends(get_db)):
    return db.execute(text(f"SELECT * FROM product WHERE name LIKE '%{term}%'")).all()  # Noncompliant

Compliant solution

Pass the values as query parameters and let the driver quote them.

def search(request):
    q = request.GET.get("q", "")
    with connection.cursor() as cursor:
        cursor.execute("SELECT * FROM item WHERE name = %s", [q])

@app.get("/products")
def products(term: str, db: Session = Depends(get_db)):
    return db.execute(text("SELECT * FROM product WHERE name LIKE :term"), {"term": f"%{term}%"}).all()

Identifiers (a sort column, a direction) cannot be parameters: map them through a fixed dict or check them against an allow-list first.
