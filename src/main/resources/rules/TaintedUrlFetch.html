Request data used as the URL of an outgoing request (requests, a requests.Session, httpx and its clients, urllib.request (Python 2 urllib and urllib2 too), an aiohttp.ClientSession) lets a caller make the server call any host: internal services, cloud metadata endpoints, admin interfaces behind the firewall. This is server-side request forgery (SSRF).

The issue names the endpoint the data comes in through and shows its path to the call.

Noncompliant code example

@router.get("/preview")
async def preview(url: str):
    return httpx.get(url).text  # Noncompliant

Compliant solution

ALLOWED_HOSTS = {"images.partner.example"}

@router.get("/preview")
async def preview(url: str):
    if urlparse(url).hostname not in ALLOWED_HOSTS:
        raise HTTPException(400)
    return httpx.get(url).text

When the rule stays silent

  • The URL starts with a literal that fixes the host: f"https://api.example/users/{user_id}", "https://api.example/" + path, or a relative "/items/..." on a client with a base URL.
  • A condition on the way checks the host: netloc, hostname, an allow-list (url in ALLOWED, a name with allowed, trusted, safe), or a "https://host" prefix.
  • A URL check helper runs on the way: validate_url(url), check_host(...), anything named after SSRF.
  • Only administrators reach the endpoint (Depends(get_admin_user), staff_member_required, an admin permission class): they configure the services the server calls.
  • The request data only goes to params=, json= or the body.
